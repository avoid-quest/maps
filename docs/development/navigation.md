# Android navigation implementation and acceptance

Development version 0.1.8 / Android code 9 adds an explicit **Avvia navigazione** action for walking, cycling, driving and the selected transit journey. Route previews and saved itineraries remain planning until that action succeeds. Navigation is Android-only; the browser and Expo Go cannot run the native session.

The local Expo module uses Ferrostar **0.57.0** for road progress, maneuver triggers and route deviation. Android owns platform GPS, the location foreground service, bounded FOSSGIS requests and offline Italian text-to-speech. This uses the published native core through UniFFI/JNA, with the existing MapLibre renderer and NativeWind interface. No Ferrostar React Native package, Compose UI, Google location service, account, paid routing provider or application backend is required.

## Implemented behavior

| Mode or boundary | Source behavior | Acceptance still required |
|---|---|---|
| Walking, cycling, driving | Start requests a fresh precise GPS fix and calculates from that position to the selected destination, including when the preview used a manual origin. Ferrostar supplies road progress/deviation; Italian maneuvers, following camera, remaining distance/time and estimates without traffic appear in the interface. | Load Ferrostar/JNA on Android; compare real paths, progress, maneuver timing and arrival for each mode. Cycling and driving need their own journeys. |
| Position quality | Active guidance requires precise permission. Fixes outside the shared age/accuracy policy, invalid coordinates or implausible jumps suspend guidance. The interface distinguishes degraded positioning and retains an explicitly labelled last position. | Denied/approximate permission, GPS disabled, tunnels, stale/inaccurate fixes and permission revocation on Android without Play services. |
| Voice | Select an installed Italian voice that declares no network requirement. Missing voice leaves visual guidance available. Mute, audio focus and stop flush speech; the app does not download a voice. | Installed/missing offline Italian voice, audio interruption, mute/unmute and prompt timing with the screen off. A successful compile does not establish audible speech. |
| Deviation and routing | Android previews, Start and reroutes share one serialized HTTP owner with at least 1.1 seconds between starts. Sustained deviation can request a reroute within a shared cooldown, movement and rolling-attempt budget. HTTP 429 enforces at least one minute or the longer supplied cooldown; cancellation stops queued/in-flight work. | Wrong turn, reconnection, HTTP failure/429, reroute limits and original-preview cancellation on the rebuilt APK. No full offline road routing or live traffic. |
| Transit journey | Start follows the selected MATO itinerary locally, preserving line, direction, stop, timing status and consultation age. It requires a recent valid itinerary and a precise fix within 50 metres of its origin. Walking/transfer completion, boarding and alighting require explicit confirmation. GPS proximity supplies advisory stop cues; only the provider's explicit same-vehicle flag joins transit legs. | Real walking access, boarding, riding, alighting and transfers. Confirm controls must work during GPS loss after the origin check. Loop/nearby-endpoint legs require manual checks; they cannot imply actual onboard presence. |
| Transit uncertainty | Missing stop proximity stays unavailable. Walking legs show the supplied map trace and explicitly lack turn instructions. The selected journey ages during guidance; departures, cancellations and connections are not continuously monitored or automatically replanned. A stale, cancelled or distant-origin journey requires replanning. | Compare against the operator and verify stale/missing/cancelled cases. MATO source freshness and reuse/availability limitations remain unresolved. |
| Lifetime and stop | Explicit Start promotes a location foreground service with a private generic notification and Stop action. UI remounts attach to the session. Stop/arrival release positioning, speech, route work and native resources. Interrupted state is local and requires explicit resume; process restart does not silently restart travel. Notification denial is visible with an in-app Stop action. | Notification Stop, Android Back, UI remount, screen-off/background operation, process/service termination, force-stop, restart, physical GPS and battery use. |
| Privacy | One bounded interrupted-session checkpoint stays in app-private no-backup storage. Stop/arrival clear it. Diagnostics retain fixed state/failure codes, without destinations, coordinates, itinerary contents or raw native errors. Online road calculation/rerouting sends current origin and destination to FOSSGIS; MATO planning sends itinerary endpoints to 5T. | Inspect the final manifest, runtime dependency graph, checkpoint cleanup and diagnostic report. Foreground-service permission does not imply background-location permission or reliable OS lifetime. |

The native module compiles and the JVM policy/transition tests pass. These checks cover deterministic request spacing/cooldown/cancellation, fix/reroute policies, session lifetime, Italian instructions and transit transitions. **The integrated Ferrostar/JNA engine, Android GPS, TTS and foreground service have not run on a usable Android runtime.** Browser simulations exercise the interface; they do not close these native gates. The production browser notice viewer was inspected at 320 and 390 pixels: Ferrostar BSD, desugared OpenJDK GPL/exception and UniFFI MPL texts expand with fetch blocked, with zero fetches and no horizontal overflow. This is offline notice/interface evidence only. Final build, signature, bundled JavaScript, notice presence and 16 KB alignment need inspection on the exact release artifact. Keep observed results in [delivery.md](delivery.md), separate from this source contract.

## Android acceptance

Build and install following [android.md](android.md). Record version/code, Android version, permissions, installed voice and network state using public routes/stops. Each row above needs an observed result for its affected mode; provider failure is an explicit outcome, and an install alone is not runtime acceptance.

1. Plan without location, then deny and grant approximate/precise location on Start. Pass: planning stays usable; guidance starts only from a valid current precise fix, and manual preview coordinates are never passed off as the device position.
2. Follow a walking route, then separate cycling and driving routes. Check maneuver/voice timing, map following/recentering, remaining estimates, wrong-turn recovery and arrival. Pass: progress matches travel, poor fixes suspend instructions, bounded rerouting recovers or gives an actionable failure, and Stop/arrival end GPS and speech.
3. Follow a transit journey with access walking and a transfer. Compare line/direction/boarding/alighting with operator information, confirm each actual transition, and test an ambiguous loop and absent endpoint. Pass: advisory distance is labelled as straight-line distance; GPS never confirms boarding/alighting; unsupported walking turns and old predictions remain explicit.
4. Repeat screen-off/background, notification denial/Stop, audio interruption, offline/429, UI remount, service/process death and force-stop/relaunch. Pass: stopped work does not return; an interrupted session requires deliberate resume; transit replan is explicit. Measure a sustained physical-device journey and battery use separately from emulator checks.

## Dependency and distribution boundary

The navigation plugin pins Kotlin **2.2.20** / Expo KSP **2.2.20-2.0.3**, D8/R8 **8.13.19**, core-library desugaring **2.1.5** and minimum Android API **25**. The resolved Ferrostar graph also upgrades Kotlin runtime, OkHttp/Okio, coroutines and AndroidX lifecycle components; regression checks must include existing map, HTTP and persistence flows. R8 is a build dependency. The APK runtime graph must still exclude Play services and Firebase.

Navigation code notices are bundled under [the module's third-party assets](../../modules/avoid-navigation/android/src/main/assets/third-party/README.md). Preserve Ferrostar's BSD notice, JNA's publisher notices and applicable JVM/Rust dependency texts and source links when updating the pinned core. Dataset licences and provider usage policies retain their separate terms.
