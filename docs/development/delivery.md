## Verified implementation and packaging

- Expo SDK 54, RN 0.81.5 and MapLibre React Native 11.5 compile through the normal build script into a locally signed arm64 APK with bundled Hermes bytecode version 96. Embedded app version, code and public revision match the release.
- APK signature verification and 16 KB ZIP alignment pass. All 18 arm64 shared libraries have ELF LOAD alignment of at least 16 KB. The signing certificate and v2 signature scheme match 0.1.5; physical upgrade preservation remains unverified.
- The release runtime classpath contains no Google Play services, Google Mobile Services or Firebase dependencies. MapLibre uses Android's default platform location engine.
- The manifest requests foreground approximate/precise location, Internet, network/Wi-Fi state and AndroidX's application-private receiver permission. Storage, microphone, overlay and vibration permissions are removed; Android cloud backup is disabled.
- Bun typechecking, zero-warning Expo ESLint and all 130 Bun tests, including 23 Python pipeline regressions, passed for 0.1.6. Both final independent Standards and Spec/privacy reviews and PR-head/merged-main CI passed. The first PR-head CI attempt hit the Python wrapper's default five-second outer timeout; the unchanged-head rerun passed. A separately reviewed tooling change now gives that test a 35-second outer budget around its unchanged 30-second subprocess limit.
- Browser checks cover selected-alternative save/reload/restore with zero route/search/GTT/location requests, original source age, explicit refresh with unchanged saved bytes, failed writes/removals and delayed-response races. Changed same-ID stops can be replaced directly; failed replacement retains the old bytes. A real MATO itinerary was saved/reloaded/restored under provider-failure fixtures; a real FOSSGIS walking response was saved. Basemap requests remained enabled. Earlier discovery, transit and diagnostics evidence does not establish native interaction or complete offline operation.
- Anonymous repository, source, latest-release, APK and checksum downloads passed. The downloaded digest matches the inspected arm64 artifact. The release is normal/latest for Obtainium's default GitHub source; an on-device Obtainium update remains unverified.

All 698 APK ZIP entries passed CRC and signing-material/private-metadata/local-path scans with zero hits. Version 0.1.6 makes compiler path mapping part of the normal build, quoting complete arguments for the pinned CMake/Ninja/shell path and rejecting unsupported delimiters or controls with a fixed error. This replaces 0.1.5's generated-only build override. The [delivery evidence](https://github.com/avoid-quest/maps/pull/6#issuecomment-6112862714) records the audit and anonymous verification. Keep release credentials outside Git and preserve the signing key across upgrades.

## Native evidence and checks outstanding

On 2026-10-11, a Google-free AOSP API 36 x86_64 software emulator booted and installed the separately audited 0.1.2/code 3 APK. The installed version was confirmed; the Google Play services package was absent. With Metro stopped and no ADB reverse mappings, a cold ActivityManager launch exited successfully with `Status: ok`.

A usable screenshot showed the app's Italian main interface beneath Android's “Process system isn't responding” dialog; the map stayed gray/loading. This confirms bundled JavaScript rendered the main UI. The system-process ANR prevented healthy interaction checks, and the final UI-hierarchy capture timed out. Its root cause was not established. The older 0.1.0/code 1 install attempt timed out and supplies no accepted baseline or upgrade evidence.

Native discovery preference/coverage behavior, compact-package startup/search/memory, transit UI, keyboard/TalkBack, map rendering, diagnostics preview/copy/off/clear, permission denial and location acquisition, lifecycle recovery, force-stop saved-travel persistence and physical same-key upgrade preservation remain unverified. The older emulator launch does not validate these controls or the released 0.1.6 package. Use the acceptance list in [android.md](android.md) and [data preparation](data.md); physical-device GPS accuracy, approximate permission behavior and battery use require separate device evidence. Neither spoken navigation nor background location is implemented. Isolated navigation prototypes pass native build checks; runtime acceptance and production adoption remain open. Private QA logs/screenshots stay outside Git and public reports.
